          Model and limits
          

            This local SQLite service places lease issuance and protected writes
            in the same transaction boundary. It demonstrates fencing and
            optimistic concurrency, not a fault-tolerant distributed lock
            service. Holder names are labels, not authenticated identities; keep
            it on loopback and use fictional text.
          

          

            Expiry uses server wall time with a persisted high-water mark.
            Backward clock changes cannot revive an observed expired lease, but
            can delay time progress until the wall clock catches up. Forward
            jumps can expire leases early. A new grant always increases the
            resource's fence. Renew never shortens a lease.
          

          

            Receipts are immutable and hash-linked. Retrying a request key
            returns the original receipt even after expiry; it does not grant a
            fresh lease. Reusing a key for a changed command is a conflict.
            Database owners can rewrite history; checksums are not signatures.
